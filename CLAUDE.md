## Commands

```bash
npm run dev      # Start development server
npm run build    # Production build
npm run start    # Start production server
npm run lint     # Run ESLint
npm run pdfs     # Puppeteer-render each page to PDF via scripts/generate-pdfs.mjs
```

There is no test suite in this repo.

## Stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript 5**
- **Tailwind CSS v4** via PostCSS (not the v3 `tailwind.config.js` pattern — config lives in `globals.css`)
- **Framer Motion** is the only animation library in use — despite what older docs may say, there is no GSAP dependency or usage anywhere in `src/`

## Architecture

**Routing**: File-based App Router under `src/app/`. Top-level routes are `/`, `/about`, `/services`, `/products`, `/contact`. The **products section is the exception** with real sub-routes: `/products/knee` (index), `/products/knee/[system]` (ski, skii, hrsk, rsk — `generateStaticParams` + `dynamicParams = false`), `/products/hip`, `/products/spine`, `/products/trauma`, `/products/arthroscopy` (index) and `/products/arthroscopy/[area]` (knee, shoulder, fibers-tapes). All are statically prerendered. All interactive pages use `"use client"`. The root layout (`src/app/layout.tsx`) wraps every page with `<Header>` and `<Footer>`. New routes also go in `routes` in `src/lib/site.ts` (sitemap) and `scripts/generate-pdfs.mjs`.

**"Detail views" are client state, not routes** (outside `/products`): clicking a service/country card does not navigate anywhere — it sets `useState` and looks up the matching object in that page's local array to render an inline detail panel. Follow this pattern for new detail views elsewhere.

**Product pages are generated from brochure HTML**: `scripts/import-brochure-pages.mjs "<brochure folder>"` reads the hand-made brochure pages and writes `src/lib/products/data/*.ts` (typed by `src/lib/products/types.ts`) plus WebP images in `public/products/<category>/`. Don't hand-edit the generated data — update the brochure HTML and re-run. Exceptions: `data/trauma.ts` and `data/arthroscopy-*.ts` were built from supplier websites (no brochure HTML) and are edited directly. To add a category (e.g. trauma), add its page to `PAGES` in the script, then wire it up in `src/lib/products/index.ts` (`categories`) and add a route that renders `<ProductPageView>`.

**Styling**: Three-layer hybrid — CSS custom properties for design tokens (defined in `src/app/globals.css`), Tailwind utilities for layout, and inline React `style` objects for dynamic/responsive values. Do not introduce a separate config-based Tailwind setup. **Gotcha:** `globals.css` has an unlayered `* { margin: 0; padding: 0 }` reset that beats Tailwind's layered utilities, so plain `p-*`/`m-*`/`pt-*` classes silently do nothing — use inline styles or the important modifier (`pt-16!`, `lg:py-[88px]!`).

**Animations**: Framer Motion is the animation layer. Shared variants and viewport config live in `src/lib/animations.ts` — import from there rather than defining inline. Use `whileInView` + `viewport` for scroll reveals, `initial`/`animate` for above-the-fold entrances, and `AnimatePresence` for conditional/state-driven transitions (mobile menu, detail panels, form success state). Stagger groups use a container with `variants={staggerNN}` propagating down to children with their own `variants`.

**Static data**: Product catalog, services, team members, office addresses, and testimonials are hardcoded as JS constants inside each page file (not in a shared `data/` directory) — each page owns its own data plus components plus layout, so these files run large. Cross-page content that appears more than once (e.g. global-presence copy on `/` vs `/about`) is duplicated by hand rather than shared, so update both call sites when changing it. `src/lib/world-map-data.ts` is generated by `scripts/generate-world-map.mjs` — don't hand-edit it.

**PDF export**: `src/components/PdfMode.tsx` detects the `?pdf=1` query param and strips animations/sticky positioning for clean Puppeteer output, used by `npm run pdfs`.

**Path alias**: `@/*` maps to `./src/*` — always use this for imports.
